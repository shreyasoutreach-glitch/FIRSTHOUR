## Interpretation

The event-detection fixture is intentionally easy to separate: suspicious cases contain strong deterministic signals such as a new beneficiary, large amount anomaly, high velocity and corroborated communication. A perfect result therefore demonstrates deterministic reproducibility on the fixture, not real-world fraud detection.

The entity-resolution suite contains only six labeled decisions. The 1.000 precision/recall result should not be generalized.

The timeline fixture has one known ordering. It validates the algorithmic path, not broad temporal accuracy.

Replay consistency of 1.000 means repeated deterministic scoring produced the same result five times.

Evidence grounding is structural: ExtractedClaim rows require a source_artifact_id. The current reported grounding rate of 1.000 is therefore a schema/property check, not an empirical claim-verification precision score.

## What is still missing

The architecture target calls for 50-100 hidden DB-backed cases. That suite should contain:
- duplicate payout;
- vendor bank-detail change;
- new beneficiary;
- dormant vendor;
- amount anomaly;
- velocity anomaly;
- conflicting evidence;
- missing evidence;
- false positive clean cases;
- cross-tenant access attempts;
- replayed imports;
- malformed source data.

The hidden suite should be run through the same API paths used by customers, not only pure helper functions.
